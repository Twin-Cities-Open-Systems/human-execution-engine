# Ratify a HEE Contract

**Why this exists:** The bug this exists to prevent: signing a contract, then editing it afterward -- even a trivial field -- invalidates the signature. It no longer matches the committed bytes, and the failure is SILENT, because a stale signature still parses as valid armor. This bit real PRs twice (#189/#190, then again in #191/#192) before the ordering became a Skill. As of 2026-09-02, `hee check signatures` enforces it; four already-broken signatures were found on that check's first run.

## When to use this

A Contract object exists with status: proposed and needs real, verifiable ratification -- not a GitHub approve-click (self-approval can't be enforced when proposer and approver share an account, discovered directly this session), an actual OPER GPG signature.

## Before you start

- The signer (OPER) has a GPG secret key, and its public key is importable by whoever will verify (this repo's account, at minimum)
- The contract passes tools/schema/validate-hee-object.py --strict as status:proposed before starting

## Procedure

**Follow this exact order. Do not reorder. Every step after signing assumes the bytes have not moved.**

Script: `tools/hee/ratify-contract.sh`

1. Stage the final content FIRST, unsigned. This flips status to ratified and inserts the ratification evidence field, so the file content becomes final before anything is signed.

   ```sh
   tools/hee/ratify-contract.sh --key <gpg-key-id> --signer <name> <contract.yaml> [<contract2.yaml> ...]
   ```

2. Only now, sign the final file.

   ```sh
   gpg --detach-sign --armor <contract.yaml>
   ```

3. Verify the hash matches what is about to be committed -- it must be byte-identical to what was signed.

   ```sh
   sha256sum <contract.yaml>
   ```

4. Verify the signature itself, and confirm it says Good signature.

   ```sh
   gpg --verify <contract.yaml>.asc <contract.yaml>
   ```

5. Commit the contract and its .asc TOGETHER, in one commit, with an ordinary git commit. Branch protection on main is the real control and binds every operator and machine equally -- see PROMPTING_RULES rule 1. The scripts/hee_git_ops.sh wrapper this step once named was retired 2026-08-31 (#456). <!-- hee-check:refs-ok  the retirement is the point -->

   ```sh
   git add <contract.yaml> <contract.yaml>.asc && git commit
   ```

6. Never edit the contract again after signing. Any further edit invalidates the signature. If a change is truly needed the contract must be un-ratified and re-signed from step 1 -- there is no way to patch a signed file without breaking its signature.


## How to verify it worked

gpg --verify <contract>.asc <contract> returns 'Good signature' when run against the exact committed file on main -- not a local copy, not an assumption. Re-check after every commit that touches the file, since the failure mode is silent (a stale signature still parses as valid armor, it just won't verify against changed content).
